# Milestone 0.1 - Provider Agent Consolidation

## Overview
This milestone focuses on the core functionality of the Provider Agent, ensuring it can be identified, its resources inventoried, and workloads deployed and tracked via gRPC.

## Features Implemented

### 1. Deployment Cycle
- **Blocking Deploy RPC**: The `Deploy` RPC now blocks until the `DockerExecutor` returns a `container_id`.
- **Correlation Mechanism**: Uses `tokio::sync::oneshot` channels to correlate gRPC requests with executor responses.
- **Timeout**: Built-in timeout of 60 seconds for deployment operations.

### 2. Identity Management
- **Identity Injection**: `IdentityManager` is integrated into the `AgentGrpcServer`.
- **Secure Info**: `GetAgentInfo` returns the node ID, Ed25519 public key, versioning, and capabilities without exposing private keys.

### 3. System Inventory
- **Resource Detection**: `GetInventory` now reports real-time CPU cores, total memory, and available memory using the `sysinfo` crate.

### 4. Workload Status
- **Real-time Tracking**: `GetWorkloadStatus` queries the Docker daemon.
- **State Mapping**: Docker container states are mapped to the protocol's `State` enum (CREATED, PENDING, RUNNING, etc.).

## Installation

### Prerequisites
- Rust (stable)
- Docker daemon running locally

### Build
```bash
cargo build --release
```

## Testing

### gRPC Interface Test
Use a gRPC client (like `grpcurl` or a custom test script) to call the following:

1. **Agent Info**: `rpc GetAgentInfo`
2. **Inventory**: `rpc GetInventory`
3. **Deploy**: `rpc Deploy` with `workload_id`, `image`, and `limits`.
4. **Status**: `rpc GetWorkloadStatus` with `workload_id`.

### Automated Tests
```bash
cargo test -p agent-api
cargo test -p agent-core
cargo test -p agent-executor
cargo test -p agent-inventory
```

## Known Limitations
- `Join` and `SolveChallenge` are not yet implemented.
- Metrics streaming is currently a stub.
- Resource limits are applied to Docker but not strictly enforced by the agent's internal scheduler (as none exists yet).
